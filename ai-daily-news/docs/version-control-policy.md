# 📋 AI Daily News 项目版本管理规范

## 🎯 版本命名规则

### 环境定义
```
开发环境 (Development)     → dev-* 分支
测试环境 (Testing)         → test-* 分支  
预生产环境 (Staging)      → stage-* 分支
生产环境 (Production)     → main/master 分支
```

### 版本号格式
```
主版本号.次版本号.修订号-环境标识.构建号

例如：
1.0.0-dev.2024031201    # 开发环境版本
1.0.0-test.2024031201   # 测试环境版本
1.0.0-stage.2024031201  # 预生产环境版本
1.0.0-prod.2024031201   # 生产环境版本
```

### 版本发布流程
```
feature/* → develop → test/* → stage/* → main

开发分支(feature/*) 
    ↓ PR审核合并
开发主干(develop)
    ↓ 集成测试
测试分支(test/*)
    ↓ 用户验收测试
预发布分支(stage/*)
    ↓ 最终验证
生产分支(main)
```

## 🚀 开发流程规范

### 分支命名规范
```
功能开发: feature/功能名称-日期
bug修复: fix/问题描述-日期
紧急修复: hotfix/紧急问题-日期
版本发布: release/v版本号
```

### 提交信息规范
```
feat: 新功能开发
fix: Bug修复
docs: 文档更新
style: 代码格式调整
refactor: 代码重构
test: 测试相关
chore: 构建过程或辅助工具变动
```

### 代码审查流程
```
1. 开发者完成功能开发
2. 提交Pull Request到develop分支
3. 至少一名同事代码审查
4. 通过CI/CD自动化测试
5. 合并到develop分支
```

## 📊 环境配置管理

### 配置文件命名
```
.env.development     # 开发环境配置
.env.testing         # 测试环境配置
.env.staging         # 预生产环境配置
.env.production      # 生产环境配置
```

### 敏感信息管理
```
❌ 禁止在代码中硬编码密码/API密钥
✅ 使用环境变量管理敏感配置
✅ 配置文件加入.gitignore
✅ 使用密钥管理服务(如Vault)
```

## 🔧 部署规范

### 自动化部署流程
```
1. 代码推送到对应分支
2. 触发CI/CD流水线
3. 自动化测试执行
4. 构建Docker镜像
5. 部署到目标环境
6. 健康检查验证
```

### 回滚机制
```
版本回滚: 一键回滚到指定版本
数据库回滚: 配套的数据迁移脚本
配置回滚: 环境配置版本管理
```
